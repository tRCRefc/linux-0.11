# 阶段三：四级虚拟内存、用户页与 COW

提交区间：`55e5a39..52e6b50`，日期：2026-08-04。

这一阶段把“内核能分配物理页”推进为“不同地址空间可以映射、共享、复制和释放用户页”，并
建立可恢复的 x86-64 页异常入口。

## 第一组：地址解析和内核映射

| 提交 | 建立的能力 |
| --- | --- |
| `55e5a39` | 沿当前页表解析虚拟地址 |
| `cf20a6f` | 把早期 2 MiB 大页拆成 4 KiB 页表 |
| `4d806c7` | 把指定物理页映射到虚拟地址 |
| `4c3b138` | 分配物理页并建立映射 |
| `e3a83ca` | 固定用户区、identity map 和物理窗口布局 |
| `f36acb0` | 建立共享的高半物理内存窗口 |
| `cf5798a` | 内核统一经物理窗口访问受管物理页 |

地址布局的核心区别是：identity map 和物理窗口都是 supervisor-only 共享映射；用户地址空间
位于独立 PML4 槽。不能因为 long mode 段基址近似为 0，就把低地址误认为合法用户地址。

## 第二组：地址空间生命周期

| 提交 | 建立的能力 |
| --- | --- |
| `9b5021c` | 新建只继承共享内核槽的空 PML4 |
| `27af9e7` | 为用户虚拟地址建立四级 4 KiB 映射 |
| `3d93ac0` | 递归释放用户页表和 CR3 根页 |
| `2cd4f65` | 切换 CR3 |

新地址空间只复制 PML4 的共享内核入口，用户页表树独立。页表页本身不共享，叶子数据页可以
通过引用计数共享。这一划分使后续 fork 能保持独立 CR3，同时实现数据页 COW。

## 第三组：页异常和写时复制

| 提交 | 建立的能力 |
| --- | --- |
| `0422fcd` | 处理匿名不存在页并返回原指令 |
| `1b0a07a` | 安装 64 位 TSS 和 `rsp0` |
| `baadfc4` | 用 `iretq` 进入 CPL3 |
| `ec78684` | 从 CPL3 页异常进入 C handler 后恢复 |
| `8cadab4` | fork 型复制时把父子叶子页改为只读共享 |
| `52e6b50` | 写只读共享页时恢复写权限或复制数据页 |

COW 决策依赖物理页引用计数：

```text
引用计数 == 1 -> 原页直接恢复 PAGE_WRITE
引用计数 > 1  -> 分配新页、复制内容、旧页引用减 1
```

父页也必须改成只读，否则父进程写入不会触发异常，子进程将观察到不该共享的修改。修改父 PTE
后需要刷新 TLB，不能只改内存中的页表项。

## 阶段结束时尚未解决的问题

阶段三只证明理想匿名缺页和理想 COW。它尚未建立任务生命周期，也没有区分所有非法保护异常。
后续三个提交补回了重要边界：

- `4ff2d83` 在进入 COW walker 前拒绝用户区外地址；
- `1844cf6` 让普通父进程能被子退出唤醒；
- `462db18` 让用户非法缺页和 OOM 只终止当前任务。
