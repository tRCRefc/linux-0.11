## 1. 审查结论

当前代码已经建立了一条技术上连贯的 x86-64 最小进程主线：

```text
UEFI 启动
-> 自有 GDT、IDT、TSS 和四级页表
-> CPL3 / int 0x80
-> fork 与独立 CR3
-> 父子只读共享和 COW
-> 软件上下文切换
-> exit 形成僵尸
-> waitpid 读取状态并回收
```

启动、物理页管理、四级页表、系统调用现场和上下文切换的基本结构是清楚的。最近 6 个提交
也符合“一个可验证能力一个提交”的原则，并且每个提交的快照都能独立通过 `make check`。

但是，现在还不能把它描述成安全、通用的 Linux 0.11 进程实现。审查发现 1 个关键问题、
2 个高优先级问题，以及若干资源语义和测试缺口。最先要处理的是页异常分类；否则 CPL3
访问 supervisor 映射时可能走入 COW 路径并错误解释大页页表。

## 3. Findings

### R-01 关键：保护异常会被无条件当作 COW，可能错误解析 supervisor 大页

位置：

- `mm/page.S:22-30`
- `mm/memory.c:314-357`
- `boot/head.S:100-125`

页异常入口只检查错误码的 Present 位：P=0 调 `do_no_page()`，P=1 就调 `do_wp_page()`。
`do_wp_page()` 随后直接按 PML4 -> PDPT -> PD -> PT 的 4 KiB 叶子结构解引用，没有验证：

- 异常是否来自 CPL3；
- 是否确实是写访问；
- 地址是否位于用户区；
- 各级表项是否存在且带有预期权限；
- PDE 是否是 2 MiB 大页；
- 是否为保留位或取指权限异常。

当前低 4 GiB identity map 和物理窗口使用 supervisor-only 的 2 MiB PDE。64 位用户代码段是
平坦地址空间，不能像原版 i386 LDT 那样用段限长阻止用户构造这些地址。因此 CPL3 读取或
写入低地址会产生 P=1 的保护异常，随后 `do_wp_page()` 可能把 2 MiB PDE 中的物理基址当成
普通 PT 页地址，并把物理内存内容当作 PTE 修改。

影响不是普通的“非法进程被终止”，而可能是低物理内存损坏、重复异常、页面泄漏或整个内核
停机。这是进入正式用户程序和权限验证前的阻断问题。

原版对照：原版 `page.s` 同样主要按 Present 位分流，但用户地址先受每任务 LDT 基址和限长
约束。long mode 已删除这一隔离机制，因此这里不能只照搬分流条件，必须显式恢复它所依赖的
安全不变量。

建议的完成标准：

```text
合法 COW 写 -> 复制或恢复可写并返回
CPL3 访问 identity/direct-map -> 当前进程以 SIGSEGV 语义退出
CPL0 非法访问 -> 明确 panic
大页、保留位、非写保护异常 -> 永不进入普通 COW walker
异常后页表和空闲页计数保持一致
```

### R-02 高：阻塞 waitpid 只对任务 0 成立，普通父进程不会被唤醒

位置：

- `kernel/exit.c:16-20`
- `kernel/exit.c:47-76`
- `kernel/sched.c:48-66`

`sys_waitpid()` 找到仍在运行的子进程后，把父进程设为 `TASK_INTERRUPTIBLE` 并调用
`schedule()`。子进程退出时只把自己设为 `TASK_ZOMBIE`，没有设置父进程的信号位，也没有把
父进程恢复成 `TASK_RUNNING`。

任务 0 是原版调度器的特殊情况：没有其他可运行任务时，`next` 默认回到任务 0，不考虑任务
0 的 state。当前单父单子探针正是依赖这一规则返回。因此测试能够通过，但任意非零 PID 的
父进程执行阻塞等待时，会一直被调度器跳过。

可复现场景：

```text
task 0 fork task 1
task 1 fork task 2
task 1 waitpid(task 2, ..., 0)
task 2 exit
```

task 1 仍为 `TASK_INTERRUPTIBLE`。如果 task 0 也在等待 task 1，系统会在 task 0 的等待循环
中反复调度，task 1 无法继续完成回收。

原版对照：原版 `do_exit()` 通过 `tell_father()` 置 `SIGCHLD`；原版 `schedule()` 在选择任务
前把持有未屏蔽信号的 `TASK_INTERRUPTIBLE` 任务改回 `TASK_RUNNING`；`waitpid()` 再清除
`SIGCHLD` 或返回 `-EINTR`。

建议在扩展进程树前恢复最小信号位图和 `SIGCHLD` 唤醒语义。直接把父进程 state 改为 running
可以作为更小的临时机制，但不能称为忠实恢复 Linux 0.11 的等待语义。

### R-03 高：非法用户缺页和 OOM 会 panic 整个内核

位置：`mm/memory.c:361-379`

`do_no_page()` 只要发现地址不在整个用户区，或者任意页面/页表分配失败，就调用 `panic()`。
用户区本身又覆盖 PML4 槽 1 到 255，没有当前任务的代码、数据、堆和栈边界。

结果是：

- 一个用户进程访问非法地址可以停止整个系统；
- 一个用户进程可以不断触碰新地址，耗尽 15 MiB 页池并停止整个系统；
- 不能区分内核缺陷与普通用户进程的段错误；
- 还无法验证失败后的页表和引用计数回滚。

原版 `oom()` 调用 `do_exit(SIGSEGV)`，`do_no_page()` 还根据 `end_data`、栈附近地址和
`executable` 决定匿名分配、文件装入或终止进程。当前尚未移植这些 task 字段和 exec，
但至少应先建立“用户错误终止当前任务，内核错误才 panic”的分界。

### R-04 中：僵尸进程保留整个地址空间直到 waitpid

位置：

- `kernel/exit.c:16-20`
- `kernel/exit.c:60-66`

当前 `do_exit()` 不释放任何用户页；`waitpid()` 回收僵尸时才调用 `free_pg_dir()`。这是为了
避免在仍使用当前 CR3 时释放它的 PML4 根页，单父单子场景下行为正确。

但原版在 `do_exit()` 中先释放代码段和数据段页表，再留下小型僵尸任务。当前每个未等待的
僵尸会保留所有数据页和多级页表，多个僵尸很容易耗尽固定的 15 MiB 页池。这个差异对内存
可见，不只是内部实现方式不同。

建议把“释放用户页表子树”和“释放 CR3 根页”分开：退出进程在自己的内核栈上清除用户映射，
调度离开后再由父进程释放空根页和任务页。这样既适应独立 CR3，也更接近原版资源生命周期。

### R-05 中：孤儿进程不会重新归属，退出顺序可造成永久僵尸和泄漏

位置：`kernel/exit.c:16-20`

当前任务退出时不扫描自己的子进程，也没有把它们的 `father` 改为 init 进程。父进程先退出后，
仍在运行或随后成为僵尸的子进程将保留一个不存在的父 PID，没有任务能通过当前父子过滤条件
回收它。

原版 `do_exit()` 把这些任务重新归属到 PID 1，并在已经是僵尸时通知 init。当前还没有正式的
PID 1/init 生命周期，因此这一项可以和最小 init/exec 一起恢复，但在此之前必须明确限制为
“仅验证父进程后退出的单层进程树”。

### R-06 中：进程闭环没有可重复的仓库内运行测试

位置：

- `init/main.c:24-32`
- `Makefile:143-161`

正式入口只初始化物理内存、打印空闲页，然后永久 `hlt`。`make check` 检查 PE 格式、架构、
未解析符号和禁用重定位，但不会进入 CPL3，也不会执行 fork、COW、exit 或 waitpid。

历史一次性探针曾验证：

```text
父 fork 返回 1，子返回 0
WNOHANG 在子退出前返回 0
子写共享用户栈触发 COW
子 _exit(37) 形成 0x2500
父 waitpid 回收 PID 1
再次等待返回 -ECHILD
task[1] 清空，空闲页恢复
```

探针按早期内核开发纪律已经删除，但仓库中没有脚本、补丁或固定测试目标可以重现这条证据。
因此普通启动通过不能证明进程代码没有回归。下一轮修复 R-01/R-02 时，应建立可重复但与生产
入口分离的 QEMU 测试方式；测试机器码或探针仍不应进入正式启动路径。

### R-07 低：汇编与 C 的现场布局依赖手工同步

位置：

- `include/asm/ptrace.h:6-27`
- `kernel/system_call.S:1-39`
- `kernel/fork.c:67-78`

系统调用汇编把 RAX 偏移硬编码为 112，`copy_process()` 又手工构造 6 个 callee-saved 寄存器
加返回地址。当前布局和反汇编完全一致，但没有生成式 offset header 或编译期交叉检查。
以后调整 `pt_regs` 或上下文帧时，C 和汇编可能各自编译成功却在运行时错位。

这与原版“task_struct 前几个字段由汇编硬编码”的风格相似。至少应在阅读指南中把它列为禁止
随意修改的不变量；等异常和系统调用入口稳定后，再考虑用专用 asm-offsets 生成步骤消除重复。

### R-08 低：构建和运行产物的仓库卫生仍可改进

位置：`.gitignore:1-7`、`Makefile:163-174`

- `/build/` 没有整体忽略，因此 EFI、ESP 和 OVMF vars 会显示为未跟踪目录；
- `make run` 复用可写的 `OVMF_VARS_4M.fd`，不同运行之间固件变量不是全新状态；
- 编译未使用原版的 `-nostdinc`。当前依赖输出证明所有头文件都来自仓库，但未来漏移植头文件时
  可能意外使用宿主机头文件。

这些不影响当前已验证启动，但会增加误暂存和环境差异风险。应分别作为小型构建卫生提交处理，
不要和 VM 或进程语义修改混在一起。

## 4. 模块级评价

| 模块 | 结论 | 主要证据 | 主要限制 |
| --- | --- | --- | --- |
| UEFI 入口 | 基础稳固 | 正确处理可变 descriptor stride、GetMemoryMap 重试和 ExitBootServices 重试 | 仅选择单个低于 4 GiB 的连续 conventional 区 |
| 早期页表 | 结构正确 | 低 4 GiB identity map、共享物理窗口、CR0.WP、CR3 安装已运行 | 全部可写可执行；用户保护异常分流有关键缺陷 |
| GDT/IDT/TSS | 最小路径正确 | 64 位 TSS.rsp0、DPL3 int 0x80 门、页异常门均已安装 | 其他异常统一停机；无 IST 和诊断现场 |
| 物理页分配 | 保留原版思想 | `mem_map[3840]`、逆向分配、清零、引用计数 | 固定 15 MiB；OOM 仍全局 panic |
| 四级页表 | 核心可用 | 创建、复制、切换、销毁、失败回滚和物理窗口 | API 假设用户叶均为 4 KiB 管理页，边界检查较少 |
| COW | 理想路径正确 | 父子只读共享、唯一引用恢复写、共享引用复制 | 入口分类不安全；无权限和非法地址测试 |
| 软件切换 | ABI 结构正确 | 保存 SysV callee-saved、切换 RSP/CR3/current/TSS.rsp0 | 无 FPU、时钟、中断和并发语义 |
| int 0x80 | 最小 ABI 正确 | 现场布局、栈对齐、相对 syscall table 和 iretq 已核对 | 无信号返回、返回前重调度和完整 syscall 表 |
| fork | 单层语义正确 | 父返回 PID、子 RAX=0、资源失败回滚、最后置 RUNNING | 无文件/inode/信号引用，进程树退出语义不完整 |
| exit/wait | 单父单子闭环成立 | 退出码 0x2500、僵尸、WNOHANG、-ECHILD 和页数恢复 | 普通父进程唤醒、孤儿、进程组和 WUNTRACED 缺失 |
| 正式启动路径 | 稳定但有限 | 默认 128 MiB 和 64 MiB QEMU 均启动 | 不进入 CPL3，不执行已实现的进程路径 |

## 5. Linux 0.11 忠实度结论

可以称为“忠实保留”的部分：

- `task[64]`、`current`、任务 0 和 PID 语义；
- `counter/priority` 的选择和重算公式；
- 动态子任务的 task_struct 与内核栈共用一页；task 0 仍使用独立 16 KiB 启动栈；
- `int 0x80` 的系统调用号及 EBX/ECX/EDX 参数约定；
- fork 的父子返回值；
- 页只读共享、写时复制和引用计数思想；
- exit wait-format 状态、僵尸以及父进程回收。

可以称为“合理目标架构替换”的部分：

- UEFI 替代 BIOS 实模式启动；
- 四级页表和独立 CR3 替代两级页表与 LDT 基址隔离；
- 软件 RSP 切换替代硬件 TSS task switch；
- CPU 级 TSS.rsp0 替代每任务完整 TSS。

只能称为“阶段性脚手架”的部分：

- 整个用户区都按匿名页处理；
- 无信号时依赖任务 0 特例完成阻塞 wait；
- 僵尸保留完整 CR3 和用户页；
- 正式入口不启动用户任务；
- 非页异常和 OOM 直接停机。

详细逐项对照见 `../reference/linux-0.11-comparison.md`。

## 8. 建议处理顺序

```text
1. 修复页异常分类和 supervisor 映射保护
2. 让非法 CPL3 缺页/OOM 终止当前任务而不是 panic 内核
3. 恢复 SIGCHLD 驱动的普通父进程唤醒
4. 提前释放退出任务的用户映射，并补充孤儿归属策略
5. 建立可重复的独立 QEMU 生命周期测试
6. 再进入 exec 和文件支持页面
7. 最后进行权限、失败回滚和压力归档
```

不建议现在先做 PIT/PIC 抢占。时钟会扩大异步状态空间，而 R-01/R-02 已经说明当前同步路径
仍有必须先固定的不变量。
