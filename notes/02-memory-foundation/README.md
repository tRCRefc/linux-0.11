## 当前分配器模型

当前只管理固定 15 MiB：

```text
PAGING_MEMORY = 15 MiB
PAGE_SIZE     = 4 KiB
PAGING_PAGES  = 3840
```

`mem_map[i]` 的含义是物理页引用计数。0 表示空闲，1 表示独占，大于 1 表示被 COW 等机制共享。
后续 `fork`、COW 和地址空间销毁都依赖这个含义，因此它不只是“空闲位图”。

## 分配和释放不变量

```text
get_free_page
-> 从高页向低页扫描
-> 找到 mem_map == 0
-> 设置为 1
-> 通过物理窗口把整页清零

free_page
-> 校验地址范围和页对齐
-> 引用计数减 1
-> 对已经为 0 的页再次释放则 panic
```

新页清零同时服务两个边界：避免把旧内核数据暴露给用户，也让新建页表天然从全零无映射状态
开始。这个行为在后续匿名缺页和多级页表分配中会反复复用。

## 这一阶段的证据

早期动态自检曾验证初始化、分配和释放后空闲页数恢复。当前正式启动继续报告：

```text
main memory pages: 3840
free memory pages: 3840
```

这只证明空载启动没有永久占用受管页。它不能证明多级页表失败回滚、COW 引用计数或进程退出
回收，那些证据分别在阶段三和阶段五建立。

## 阶段限制

- 只选择一个低于 4 GiB 的连续 conventional memory 区间；
- 不管理稀疏物理内存和 4 GiB 以上 RAM；
- 没有伙伴系统、slab 或交换；
- OOM 的进程级结果直到 `462db18` 才恢复。

详细函数阅读见 [DAY 2 学习记录](day-02.md)。
