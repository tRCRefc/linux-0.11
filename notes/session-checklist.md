# 开发 Session 笔记检查清单

本清单与根目录 `AGENTS.md` 配合使用。它保证新的对话 session 不依赖旧对话上下文，也能沿提交链
继续维护学习笔记。

## Session 开始

```text
[ ] 读取 AGENTS.md
[ ] 读取 notes/README.md
[ ] 读取当前阶段 README.md
[ ] 读取 NEXT_STEP.md，但把它视为计划而不是完成状态
[ ] 检查 git status 和最近提交
[ ] 确认 notes/ 中记录的基线是否落后于 HEAD
```

如果笔记落后，先根据 `git log`、提交 diff 和已有验证证据补齐，再开始新的能力修改。

## 开发过程中

每个独立能力都记录以下四栏：

| 项目 | 必须回答的问题 |
| --- | --- |
| 提交线索 | 哪个 commit 或待提交原子改动建立了能力？ |
| 行为 | 调用者、启动路径或子系统现在能观察到什么？ |
| 证据 | 编译、链接、反汇编、QEMU 各自证明了什么？ |
| 限制 | 哪些行为仍然是脚手架、未验证或明确延期？ |

临时探针只记录有长期学习价值的结果。探针代码删除后，要明确写出“证据保留、探针未进入正式
入口或提交”，避免以后把普通启动误当成专项回归。

## 未提交工作结束前

如果源码改动仍未提交，在对应阶段增加“进行中”小节，至少写出：

```text
基线 commit
改动文件和目标行为
已经通过的检查
仍缺少的运行验证
```

不要为未提交工作虚构 commit 号，也不要把计划状态写成 implemented。

## Commit 完成后

```text
[ ] 用真实 commit hash 和标题替换“进行中”标记
[ ] 更新阶段提交区间
[ ] 更新 notes/README.md 当前基线
[ ] 补充实际验证输出的关键结果
[ ] 保留仍未完成的限制
[ ] 确认临时探针不在正式代码中
```

如果提交开启新的系统责任，创建新的阶段目录和 `README.md`，然后在总索引增加一行。

## Session 结束

执行或等价检查：

```bash
git status --short --branch
git status --short notes AGENTS.md NEXT_STEP.md
git diff --cached --name-only
```

结束条件：

- 文档的跟踪状态符合根目录 `MIGRATION.md`：迁移快照期间纳入提交，清理提交后保持本地 ignored；
- 暂存区不包含 `build/` 生成产物；
- 当前阶段笔记覆盖本 session 的正式能力变化；
- 最终交接说明本次更新了哪份阶段笔记。
